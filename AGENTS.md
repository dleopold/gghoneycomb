# AGENTS.md

Guidelines for contributors and AI agents working on gghoneycomb.

## R Package Development Workflow

### Infrastructure Changes

Use `usethis::use_*()` functions for all infrastructure modifications: -
`usethis::use_package("pkg")` - add runtime dependency -
`usethis::use_package("pkg", type = "Suggests")` - add dev dependency -
`usethis::use_test("feature")` - create test file -
`usethis::use_r("feature")` - create R source file

### Core Commands

``` r
devtools::load_all()    # Load package for interactive testing
devtools::document()    # Regenerate NAMESPACE and man/*.Rd from roxygen2
devtools::test()        # Run testthat tests
devtools::check()       # Full R CMD check
```

### Hands-Off Files

**Never edit manually:** - `NAMESPACE` - generated by roxygen2 -
`man/*.Rd` - generated by roxygen2

These files are regenerated by `devtools::document()`. All documentation
lives in roxygen2 comments (`#'`) in R source files.

## ggplot2 Extension Conventions

### ggproto Inheritance

- Inherit from appropriate ggplot2 classes: `Geom`, `Stat`, `Scale`,
  etc.
- Use `ggproto("GeomHoneycomb", Geom, ...)` pattern
- Override only necessary methods; rely on parent defaults

### Dependencies

- Use `Imports` (not `Depends`) for ggplot2 and other packages
- Access ggplot2 internals via `ggplot2::` prefix
- Use `@importFrom rlang .data` for tidy evaluation (avoids R CMD check
  NOTEs)

### Tidy Evaluation

``` r
#' @importFrom rlang .data
```

Use `.data$column` in aes mappings and dplyr operations to avoid
undefined global variable warnings.

## Testing Approach

### Start Simple

1.  **Data-based tests first**: Test that stats/geoms produce expected
    data structures
2.  **Use `layer_data()`**: Extract computed data from ggplot objects
    for assertions
3.  **Test edge cases**: Empty data, single row, NA handling

### Visual Testing

Add `vdiffr` only when: - Visual output is critical to the feature -
Data-based tests cannot capture the behavior - You have stable reference
images

``` r
# Only if needed:
usethis::use_package("vdiffr", type = "Suggests")
```

## renv Policy

### Configuration

- `snapshot.type = "explicit"` - only captures DESCRIPTION dependencies
- `renv.lock` is **git-ignored** - CI installs from DESCRIPTION

### Workflow

``` r
# After adding/changing dependencies:
renv::snapshot(dev = TRUE)

# Sync local environment:
renv::restore()

# Check status:
renv::status()
```

### Why `dev = TRUE`?

`renv::snapshot(dev = TRUE)` includes Suggests dependencies in the
lockfile, ensuring dev tools (testthat, knitr, etc.) are captured for
local development.
